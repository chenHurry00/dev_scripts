# 分配员手册

## 适用范围

本手册面向控制面板中的分配员角色。

## 职责范围

分配员负责平台日常运维工作，不负责底层系统开发。

**主要职责**

- 管理服务器接入状态
- 执行容器分配与回收
- 调整容器资源配额
- 管理镜像库与环境备份
- 监督 GPU 用量与额度
- 协助用户解决日常使用问题

## 操作边界

分配员不应执行以下操作：

- 直接修改宿主机 Docker 底层配置
- 绕过控制面板手工修改受管容器
- 在未确认数据位置的情况下直接重建或删除容器
- 在无记录的情况下调整用户额度和资源配额

!!! warning "操作规范"
    分配员应优先通过网页面板完成操作。  
    删除、重建、额度调整等关键操作应确保在日志中可追溯。

## 常用操作流程

### 添加服务器

标准流程：

1. 确认目标宿主机已部署 Agent
2. 在服务器管理中填写主机地址、端口、Token
3. 配置挂载根目录
4. 保存后检查状态与能力

操作入口：

1. 打开左侧 `服务器`
2. 点击右上角 `+ 添加服务器`

图 8 所示为添加服务器弹窗。

![注册服务器弹窗](../assets/images/admin/09-server-add-modal.png)

**图 8** 添加服务器弹窗

填写时重点注意：

- `名称` 用于页面识别
- `服务器标识 ID` 建议固定，避免频繁修改
- `主机 IP / 域名` 与 `Agent 监听端口` 应与实际 Agent 配置一致
- `SSH 显示地址` 为用户登录时显示的地址
- `挂载根目录` 决定容器可选挂载范围

至少确认：

- 服务器显示在线
- 挂载目录检查通过
- GPU 状态符合预期
- 如需磁盘限额，服务器显示支持

### 分配新容器

标准流程：

1. 选择目标服务器
2. 选择镜像
3. 填写使用者标识
4. 填写容器登录用户
5. 设置 CPU、内存、PIDs、磁盘上限
6. 按需启用 GPU
7. 确认额外业务端口数量
8. 创建后核对 SSH 命令、端口映射和运行状态

操作入口：

在仪表盘或容器管理页点击 `+ 分配容器`

建议填写顺序：

1. 选择目标服务器
2. 选择镜像
3. 填写使用者标识和登录用户
4. 设置 CPU / 内存 / PIDs / 可写层磁盘上限
5. 如需 GPU，勾选并确认设备
6. 检查 SSH 端口、网络模式、额外业务端口和挂载目录

创建后立即核对：

- 容器状态是否为 `running`
- SSH 命令是否可复制
- 端口映射是否符合预期
- 占用栏是否正常刷新

!!! tip "使用者标识"
    GPU 统计、额度及跨服务器同名用户聚合优先按"使用者标识"进行。  
    同一实际用户应保持同一使用者标识，避免随意变更。

### 在线修改资源

适用范围：

- CPU
- 内存
- PIDs
- 可写层磁盘上限（仅在服务器支持时）

建议流程：

1. 查看当前占用情况，决定调整幅度
2. 小幅度调整优先采用在线修改
3. 修改后刷新确认是否生效

标准操作：

1. 在容器管理页确认当前占用
2. 点击 `更新 / 备份`
3. 小幅调整 CPU / 内存 / PIDs 时优先使用在线修改
4. 涉及 GPU、磁盘上限、运行参数、端口映射时采用重建

### 备份与重建

适用场景：

- 用户环境需要保留
- 重建前需要可回退镜像
- 需要从已有备份恢复

应区分：

**临时快照镜像**

- 主要服务于重建流程

**手动备份镜像**

- 用于长期保留，不应自动删除

执行前建议确认：

- 用户数据是否均在挂载目录
- 当前是否需要先手动备份
- 端口、GPU、运行参数是否需要一并调整

### 删除容器

删除前至少确认：

- 用户是否仍在使用
- 数据是否已保存在挂载目录
- 是否需要先手动备份镜像

## 日常维护规范

### 每日巡检

建议每日至少检查一次：

- 服务器在线状态
- 容器是否存在 `missing`、异常占用或明显状态异常
- GPU 超额用户
- 低效占用 GPU 用户
- 最近失败的操作日志

推荐巡检顺序：

1. 查看仪表盘
2. 检查服务器是否在线
3. 查看容器管理中的状态和占用
4. 检查 GPU 计算时中是否存在异常用户
5. 查看操作日志确认是否存在失败操作

### 每周维护

建议每周至少执行一次：

- 回顾本周 GPU 超额用户
- 评估是否需要调高基础额度或发放临时额度
- 清理已确认无用的旧镜像
- 导出一次配置

配置导入导出入口位于 `操作日志` 页面右上角。

## 额度管理建议

### 基础额度

适用于：

- 长期稳定的资源需求变化
- 某类用户持续更高负载场景

### 临时额度

适用于：

- 某个训练周期
- 某次短期项目冲刺
- 某段时间的集中实验

!!! note "额度管理原则"
    长期需求调整基础额度。  
    短期需求增加临时额度。  
    临时任务结束后及时复核是否需要恢复默认。

在 `GPU 计算时` 页面中：

- 上半部分调整全局默认基础额度和统计保留天数
- 中间用户表显示本周已用 / 有效额度、超额量和当前活跃 GPU
- 用户操作列可执行 `明细`、`复制链接`、`重置链接`、`基础额度`、`临时额度` 操作

## 常见问题处理

### 容器创建失败

优先检查：

- 目标服务器是否在线
- 镜像是否存在
- 端口是否冲突
- Docker / Agent 是否正常
- 操作日志是否包含明确错误信息

### 容器已创建但面板未识别

排查顺序：

1. 刷新容器管理页
2. 检查 Agent 能否读取容器列表
3. 查看是否存在同名记录冲突
4. 必要时执行接管或重建流程

### GPU 不可用

优先检查：

- 服务器能力检查是否显示 GPU 支持
- 分配时是否启用 GPU
- 镜像环境是否满足 CUDA 使用需求
- 宿主机驱动或 NVIDIA 运行时是否异常

### SSH 登录异常

优先检查：

- SSH 命令是否正确
- 容器是否处于运行状态
- SSH 端口映射是否存在
- 用户密码或公钥是否按预期配置

## 工作节奏建议

建议形成固定工作节奏：

- 每日检查运行状态、容器异常及 GPU 超额情况
- 每周执行额度复核与镜像清理
- 每月复核整体资源策略及热点用户情况

通过定期巡检，分配员可避免在问题爆发后被动处理。
