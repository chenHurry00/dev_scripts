# 用户手册

## 适用对象

适用于使用平台分配的 Docker 容器进行开发、训练、调试和服务部署的普通用户。

## 你现在拿到的是什么

与过去直接在宿主机上开发不同，现在平台分配给你的通常是：

1. 一个独立容器。
2. 一个容器登录账号。
3. 一个 SSH 登录端口。
4. 若干个业务映射端口。
5. 一个挂载目录。
6. 可能附带 GPU 使用权限。

你应把它理解成：

1. 这是你的开发环境。
2. 但不是宿主机本身。
3. 你可以在容器里安装依赖和运行程序。
4. 但资源、端口、GPU 使用都属于受控范围。

## 与过去宿主机开发的主要区别

## 1. 你登录进去的是容器，不是宿主机

这意味着：

1. 容器内的操作主要影响当前容器。
2. 不应再把宿主机当成自己的开发环境去改。

## 2. 重要数据不要只放在容器系统层

容器可以被重建。

如果重要数据只放在容器内部普通目录，而不在挂载目录下，那么：

1. 重建后可能丢失。
2. 分配员很难帮你完整恢复。

!!! warning "最重要的原则"
    代码、模型、数据和实验结果应优先放在挂载目录中。

## 3. 对外服务必须通过映射端口访问

现在不是随意占用宿主机任意端口。

你需要：

1. 知道自己被分配了哪些业务端口。
2. 在容器内监听对应容器端口。
3. 从宿主机映射端口对外访问。

## 4. GPU 使用会被统计

平台会统计：

1. 你占用了哪些卡。
2. 大致用了多久。
3. GPU 利用率和显存占用情况。

因此不建议长期空跑、低利用率占卡或任务结束后不清理进程。

## 如何登录容器

分配员通常会给你以下信息：

1. SSH 登录命令。
2. 登录用户名。
3. 密码或公钥方式。
4. 业务端口映射规则。

典型命令示例：

```bash
ssh -p 32000 youruser@server-ip
```

登录后建议先确认当前环境：

```bash
whoami
hostname
pwd
```

通常你会发现：

1. `hostname` 显示为容器名或容器 ID。
2. 当前环境是容器内部。

## 挂载目录怎么用

分配员通常会把宿主机某个目录挂载到容器内，例如 `/workspace`。

建议你把以下内容优先放在挂载目录：

1. 项目代码。
2. 数据集。
3. 模型权重。
4. 日志与输出结果。

这样做的好处：

1. 容器重建后通常仍能保留。
2. 不容易随着容器系统层变化而消失。

## 如何传文件

推荐做法是：

1. 先把文件传到挂载目录。
2. 再登录容器确认文件是否可见。

传完后建议检查：

```bash
cd /workspace
ls
du -sh .
```

如果文件已经在挂载目录中，容器里通常就能看到。

## 如何对外提供服务

如果你在容器里启动：

1. Web 页面
2. API
3. Jupyter
4. Gradio
5. TensorBoard

需要先理解自己的端口映射。

例如分配员给你的规则可能是：

```text
server-ip:32200 -> container:8000/tcp
server-ip:32201 -> container:8001/tcp
```

这表示：

1. 你在容器内监听 `8000`
2. 外部访问宿主机 `32200`

例如：

```bash
python -m http.server 8000 --bind 0.0.0.0
```

则外部访问地址通常是：

```text
http://server-ip:32200
```

!!! tip "监听地址"
    服务应监听 `0.0.0.0`。  
    如果只监听 `127.0.0.1`，外部通常访问不到。

## 如何理解资源限制

你的容器可能被设置了：

1. CPU 上限。
2. 内存上限。
3. PIDs 上限。
4. 可写层磁盘上限。
5. GPU 权限。

这意味着你不应默认自己拥有宿主机全部资源。

如果实际开发不够用，应联系分配员申请调整，而不是自行猜测平台失效。

## 可写层磁盘上限是什么意思

它只限制：

1. 容器自身系统层写入。

不限制：

1. 挂载目录。
2. 独立数据盘。
3. Docker volume。

因此，大文件和长期保留数据更应该放在挂载目录。

## 如何使用 GPU

如果你的容器被分配了 GPU，可以先检查：

```bash
nvidia-smi
```

如果能看到 GPU，说明基本可用。

你需要知道：

1. GPU 不是完全私有资源。
2. 平台会统计用量。
3. 长期低利用率占卡会影响其他人。

建议：

1. 需要时再启动训练或推理。
2. 任务结束后及时退出无用进程。
3. 模型、日志、输出结果写入挂载目录。

## 什么时候联系分配员

以下情况建议直接联系分配员：

1. 需要更多 CPU、内存、PIDs、磁盘。
2. 需要更多业务端口。
3. 需要新的基础镜像。
4. 需要备份当前环境。
5. 需要重建容器。
6. GPU 看不到或环境异常。

## 常见误区

### 误区 1：把容器当宿主机

错误理解：

1. 觉得自己可以像以前一样随意改系统环境。

正确理解：

1. 你在容器内开发，不应把宿主机当成个人环境。

### 误区 2：把重要数据只放在容器内部普通目录

错误理解：

1. 认为容器永远不会重建。

正确理解：

1. 重要数据应放在挂载目录。

### 误区 3：服务启动了就一定能从外部访问

错误理解：

1. 只要程序跑起来，宿主机自然能访问。

正确理解：

1. 必须对照分配给你的端口映射规则。
